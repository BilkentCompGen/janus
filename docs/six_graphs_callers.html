1 · Connected-component structure of the 6 graphs

Pruning removes the shared backbone, so the graph falls into many disconnected pieces — the candidate events a caller inspects.

Every graph keeps one stubborn ~13,083-node piece — a persistent satellite/complex tangle no pruner breaks. The full graph keeps a 1.14M-node giant component (the connected backbone) that pruning dissolves.

2 · Recall by category — the full graph is the maximum possible

% of truth variants of each type found. The full graph is the ceiling (it carries all signal); every pruned graph is measured against it.

Recall is identical across all six graphs for every category except DUP. DUP needs the shared backbone to measure its depth ratio, so it erodes as pruning gets aggressive (75% → 54%). This is the one place pruning costs recall — and exactly why the uc (copy-aware) family exists. SNP/INDEL/CPX are shown at their typed recall (low — see §4).

3 · Precision — and why pruning is really a precision tool

The full graph over-produces massively. "Any-site" = fraction of all calls that land on a real variant of any type (noise vs real).

categorytruthcalls (full graph)

DUP dominates the noise: 120,618 calls for 130 real duplications. The tumour/normal depth ratio is genome-wide and its noise band (backbone p95=1.43) overlaps the DUP threshold, so windowed elevation fires everywhere. This is the same base-rate wall that killed the per-core copy pruner earlier.

Per-category precision is a lower bound: much of each type's "false positives" are real variants of a different type (a SNP makes a normal-only stretch that reads as a small DEL). INV is the cleanest single type (~20%). The honest precision signal is ANY-SITE, and it climbs steeply with pruning: 20% → 72%.

4 · SNP & short-indel: detectable, but not typeable

Two very different numbers, both measured:

SNPINDEL
detectable (a somatic signal sits at the locus)90.1%89.3%
typeable (callable specifically as that type)4.3%8.8%

The graph flags ~90% of small variants — a normal-only reference core plus a novel tumour core. But a SNP, a short indel, and a small deletion all produce the same shape: a small normal-only + novel bubble. From graph topology and coverage alone they are not separable. Typing them needs the core sequence, which the signature-only graph does not carry.

So for small variants the honest deliverable is a single "small-variant present" track at ~90% recall, not separate SNP/indel calls. This mirrors the complex-SV situation: detectable as "something somatic here", typeable only with more information.

This is a genuine property of a sequence-free graph, not a caller bug — and worth stating plainly in the paper.

Conclusions

  • The algorithms do disconnect the graph — 75k–104k pieces, ~95k somatic-bearing, almost all ≤48 nodes (typeable size).
  • Recall ceiling (full graph): DEL 93%, INS 90%, INV 89%, DUP 75%; small variants 90% detectable; CPX is hardest. Pruning preserves all of it except DUP, which needs the shared backbone.
  • Precision is the pruning payoff. The full graph is signal-rich and noise-rich (any-site precision ~20%); pruning lifts that to ~72% at minsize while holding recall. Pruning is a denoiser, not just a compressor.
  • DUP is the dominant noise source (120k spurious calls) — the depth ratio is too noisy genome-wide. A junction-gated DUP caller (only call a duplication where a back-edge junction bounds the elevated span) is the clear next improvement.
  • SNP / short-indel / small-DEL are one detectable-but-untypeable class in a sequence-free graph. Honest output there is a single "small variant here" track at ~90%, not three separate typed tracks.
  • These per-category detectors ARE the extra algorithms requested — a run-scan caller (LOSS-run→DEL, windowed-ratio→DUP, strand-1-run→INV, novel-cluster→INS, jump-edge→CPX, small-bubble→small-variant). Recall is validated against the independent signature metric; precision is a rough lower bound pending the DUP and small-variant refinements above.
