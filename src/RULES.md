# Coding rules

1. Keep it simple and short.
2. No advanced C++.
3. No inline or pointer functions.
4. No documentation, no comments in the code.
5. No defensive coding.
6. No long unnecessary if-elses and over-checks.
7. Assume input is in the right format and shape.
8. Every file covers a specific part of the pipeline, so files should not be too long.
9. No code duplication. Every written code must be fully unique; if there is a high portion of overlap, you are doing something wrong.
10. If you can do it in 1-2 lines, don't do it in 5-6 lines for "future-proofing" or "error handling". No overengineering whatsoever.
